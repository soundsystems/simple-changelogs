# Simple Changelogs Testing-Note Maintenance Contract

Maintain scoped customer/developer histories and established release-note
outputs. Runtime decisions live in `SKILL.md` and its routed references;
repository policy and the current request define authority.

## Testing-note scope

Mobile test-build preparation and finalization include a durable first draft
of practical tester instructions. Later agents refine that draft. Instructions
bind to the actual application, platform, source revision, and build artifact;
new artifacts retain separate histories even when the public version is shared.
TestFlight copy and Play testing-track copy are derived for their own audiences,
locale conventions, and current provider limits.

The source model combines inspected product behavior, build evidence, existing
tester instructions, and unresolved regression needs. A customer changelog is
supporting context, not a complete test plan. Secret values, customer records,
and unsupported verification claims never belong in instructions.

All distributions forbid em dashes in newly authored or edited release copy
unless explicitly requested by the user. Repository house style alone cannot
create an exception; untouched released history remains intact.

## Validation and limits

Package contracts verify routing, portable paths, declarations, and guidance
checkpoints. Behavioral fixtures cover first-draft ownership, later extension,
new artifacts, and Android copy limits. A model adapter is required to run those
behavior cases; package validation alone does not prove their outputs.

Guidance does not install credentials, submit a build, send tester messages,
promote a track, or independently publish metadata. Finalized notes may remain
prepared locally when provider operations are outside the task. Publication
claims require readback from the exact authorized destination. Update the
routed testing reference and behavior cases together when this contract changes.
